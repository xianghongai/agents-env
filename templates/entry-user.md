# 用户级指令入口

**开工前先读 `~/.agents/AGENTS.md`**（当前用户主目录下），那是跨 Agent 的用户级规则正本，个人工程规则全部写在那里。

本文件只是指针，不重复其内容，也不为任何一家开分支：各 Agent 严格对齐同一套规则。**新增或变更规则一律只改 `~/.agents/AGENTS.md`**，不要写回本文件。

## 持久上下文（Instructions）

常驻注入、每次会话都生效的规则层。

- 规则正本是 `~/.agents/AGENTS.md`。各 Agent 按自己的约定路径加载各自的入口文件，本文件即是其中之一；所有入口文件内容保持一致，都只指向同一份正本。
- 这一层放长期有效的约定：工程规范、目录职责、安全约束、禁止事项、验证要求。
- **任务流程不写进这一层**，拆成 Skill 按需加载；指令文件堆满流程会让每次会话都付出上下文代价。

## Skills（按需加载）

只在任务匹配时才读取的能力层。

- 正本是 `~/.agents/skills/<name>/SKILL.md`，详细材料放按需读取的 `references/`。
- `~/.agents/skills/` 已是跨 Agent 的公共 Skill 目录，多数 Agent 原生读取，无需额外配置。
- 仍只读自身私有 Skill 目录的 Agent，在该目录下建符号链接指向正本；私有目录已有自带内容时逐个链接，不整目录替换。
- 新增 Skill 时在 `~/.agents/skills/` 建目录；不要把正本放进某个 Agent 的私有目录。
- **不要假设项目级覆盖用户级**：各 Agent 的优先级并不一致，有的用户级反而优先于项目级，按当前 Agent 的实际规则确认。

---

各 Agent 自己的目录仍然拥有模型、权限、Hook 与 MCP 等产品专属配置。那一层不是指令，不在本文件的对齐范围内。
