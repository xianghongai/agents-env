# 入口模板维护指南

入口文件只负责指路，不承载规则本身。同一 Scope 下各 Agent 的正文**完全一致**，不为任何一家开分支：这是这套模板存在的前提，改动前先确认新内容对所有 Agent 都成立。

## 文件职责

| 路径 | 职责 |
| --- | --- |
| `entry-user.md` | 用户级通用正文，指向 `~/.agents/AGENTS.md` |
| `entry-project.md` | 项目级通用正文，指向仓库根 `AGENTS.md` |
| `fragments/` | 少数 Agent 的变体片段，按需取用 |

## `{{TITLE}}` 占位符

只有 `entry-project.md` 用到它（`entry-user.md` 的标题是固定的）。替换值由入口文件的相对路径决定：

| 入口路径 | 渲染出的标题 |
| --- | --- |
| 含 `/`，即落在子目录，如 `.<agent>/rules/<入口文件>` | `# 项目上下文入口` |
| 不含 `/`，即落在仓库根，如 `<AGENT>.md` | `# <AGENT>.md`（以文件名为标题） |

也就是说，落在 Scope 根的入口以文件名作标题，落在子目录的统一叫「项目上下文入口」。

## 变体

变体**必须在注册表中显式声明**路径，脚本据此精确取用，不做文件探测。

### `template_override`：整份替换

通用正文完全不参与，片段内容就是最终结果。

> **注意：override 不做 `{{TITLE}}` 替换。** 脚本直接 `cat` 片段文件，占位符会原样留在输出里。整份替换的片段请把标题写死。

### `template_frontmatter`：只加前置块

片段内容拼在通用正文**之前**，正文仍走 `entry-<scope>.md` 并正常替换 `{{TITLE}}`。用于那些要求 YAML frontmatter 才能识别规则文件的 Agent。

## 命名约定

后缀表示种类：`.md` 是整份覆盖，`.frontmatter` 是前置块。中间的 Scope 段按**这个片段服务于哪些 Scope** 决定：

| 命名 | 含义 |
| --- | --- |
| `<agent-id>.<scope>.<后缀>` | 只服务该 Scope |
| `<agent-id>.<后缀>` | 两级共用，内容与 Scope 无关 |

两级内容相同就共用一个文件，不要复制成两份：复制出来的两份必须手动保持同步，迟早会漂移。反过来，只要两级有任何差异，就拆成各带 Scope 的两个文件，不要用条件判断把差异塞进同一个片段。

判断依据是查厂商文档：两级支持的 frontmatter 字段是否一致、写法是否相同。**查证结论记在注册表对应条目的 `references` 里，不写进本文档**：厂商会改名、会停运，把某一家的结论固化在通用文档里，过期了没人知道该删哪一句。


## 改完怎么验

正文改动会影响所有 Agent 的入口文件，跑一遍容器测试确认渲染与幂等未被破坏：

```bash
docker compose -f test/compose.yaml run --rm test
```
